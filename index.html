Chapter overview

Why length generalization?

Why should a rule learned on short sequences keep working on longer ones? Distinguish representability, learning, and generalization.

We want models to apply what they learn to problems larger than those encountered during training. A model trained on short sequences might later need to copy a longer passage, count events across a longer record, or check the structure of a larger program. When the underlying task stays the same, can the model carry out the same computation on inputs longer than the training examples? This is the problem of length generalization.

One motivation is to make better use of training data and computation. Long examples can be costly to collect, annotate, and process, and training cannot cover every input length a model may encounter. If shorter examples are sufficient to learn a reusable rule, we may reduce the need for long training examples while still handling longer inputs at test time. This does not necessarily mean that fewer training examples are needed overall: generalizing across lengths and learning from fewer samples are distinct goals.

Length generalization also asks whether the learned computation continues to work as the task grows. Counting, copying, and checking nested structure provide simple settings in which the same rule applies across lengths. A larger context window allows a model to receive longer inputs, but does not ensure that it processes them correctly. Throughout this tutorial, we therefore distinguish the lengths seen during training from the maximum length the model can process.

To understand what a transformer can learn from shorter inputs, we separate three questions:

  1. Representability: Does there exist a transformer that computes the desired function across input lengths?
  2. Learnability: Can a training procedure find a model that computes the function on the training distribution?
  3. Length-generalizable learnability: Does training on bounded lengths yield a model that also computes the function on longer inputs?

A positive answer to one question does not settle the next. Constructing suitable weights establishes that a computation is possible, but does not show that training will find them. Likewise, perfect accuracy on shorter inputs does not establish length generalization. For example, a rule that checks whether parentheses are correctly nested only up to the maximum training length can agree with the desired recognizer on every training input and fail on every longer valid string. The observations alone do not distinguish that rule from a recognizer that works at all lengths. We therefore need to understand which computations the architecture can represent and which solutions the learning procedure favors.

Our main tool is C-RASP, a small programming language for computations over sequences. Its programs combine predicates on positions with counts over prefixes. A fixed program describes the same computation at every input length, making it possible to state an algorithm without choosing a maximum sequence length. C-RASP also connects these algorithms to transformers: prefix counts can be represented using attention, while feedforward layers implement comparisons and Boolean operations. This connection gives constructive expressivity results; it does not by itself establish a learning guarantee.

Informal theorem: C-RASP and length generalization.

Suppose a sequence task over a fixed finite alphabet is described by one fixed C-RASP program. Then, under the idealized learning framework of Huang et al. (2025), transformers eventually generalize to longer inputs: for every sufficiently large context length 𝑛, the selected transformer computes the task correctly on all inputs up to length 𝑛, although training covers only inputs up to length 𝑛2.

This assumes that the learner fits every input through the training length, approximately minimizes the framework’s complexity regularizer, and satisfies its positional restrictions. The result also covers C-RASP extended with periodic position predicates and local relations that depend only on relative position.

Why C-RASP matters. A program supplies a length-independent algorithm that can be compiled into the transformer representations required by the theorem. Expressibility in C-RASP is therefore a sufficient condition for this idealized guarantee. It does not guarantee that gradient-based training finds the algorithm or give a practical training-length threshold.

We first develop C-RASP through a worked parentheses recognizer and examples of what the language can and cannot express. We then explain its compilation into transformers and the role of positional information. This leads to the length-generalization framework of Huang et al. (2025), which connects suitable representations to eventual generalization under an idealized inference procedure. We keep this guarantee separate from ordinary gradient-based training and discuss what it does, and does not, tell us about the training lengths required. The final sections outline how additional computation through chain of thought changes the question and which limitations remain open.

Foundations

The complexity classes, sequence tasks, and causal transformer model used throughout the tutorial.

Computational complexity

Complexity classes describe which problems can be solved with specified computational resources. For transformers, circuit complexity is useful because it separates the amount of computation performed in parallel from the number of sequential stages.

A Boolean circuit is a directed acyclic graph whose gates compute Boolean operations. Its size is the number of gates; its depth is the longest path from an input to the output. Gates at the same depth can be evaluated in parallel. To recognize inputs of arbitrary length, we use a family of circuits (𝐶𝑛)𝑛≥1, with one circuit for each input length 𝑛. Polynomial size means at most 𝑛{𝑂(1)} gates, while constant depth means a bound independent of 𝑛. We use logspace-uniform families: one algorithm constructs 𝐶𝑛 from 𝑛 using 𝑂(log𝑛) working space, rather than choosing unrelated circuits separately at every length (Immerman, 1999, Chapter 5).

Three circuit classes. The following classes all require polynomial size but differ in their gates and depth:

  • 𝖠𝖢0: Constant-depth circuits with AND, OR, and NOT gates. AND and OR have unbounded fan-in: a single gate may combine arbitrarily many inputs. For example, testing whether a string contains an 𝑎 needs only an OR over the input indicators. Parity cannot be computed in this class.
  • 𝖳𝖢0: Constant-depth circuits that additionally allow unbounded-fan-in majority gates. A majority gate tests whether more than half its inputs are true; this gives the same class as allowing unweighted threshold gates. This class contains both majority and parity.
  • 𝖭𝖢1: Circuits of depth 𝑂(log𝑛) with AND and OR gates of fan-in at most two, and NOT gates. The additional depth allows information to be combined through a tree. For example, a balanced tree of constant-size XOR circuits computes parity in logarithmic depth.

The classes satisfy

𝖠𝖢0⊂𝖳𝖢0⊆𝖭𝖢1.

The first inclusion is strict; whether the second is strict remains open. Thus, constant depth alone does not determine expressive power: the permitted gates matter as well (Viola, 2023, Chapter 10).

Turing-computable functions. A total function is Turing-computable if a single Turing machine halts and returns its value on every finite input. Unlike the circuit classes above, this imposes no polynomial time or small-depth bound. For a language, the corresponding notion is decidability: the machine must halt with the correct acceptance decision on every input. Computability asks whether an algorithm exists; complexity asks which resources it needs.

Why these classes matter for transformers. A fixed number of transformer layers suggests a bounded number of parallel stages, but a circuit simulation must also account for arithmetic precision and the operations within each layer. With 𝑂(log𝑛)-bit arithmetic and feedforward maps computable in space linear in their input representation, a fixed transformer forward pass can be simulated in 𝖳𝖢0 (Merrill and Sabharwal, 2023). Claims of Turing completeness concern a different resource regime and must specify how computation can grow, for example through additional generated tokens or iterations. Neither a circuit upper bound nor Turing completeness establishes that training will learn a solution that generalizes to longer inputs.

Formal languages and sequence tasks

We use a small set of tasks to study which computations transformers can represent and learn across input lengths. Their rules are easy to state, but involve different operations: counting, tracking order, checking nested structure, and reproducing a sequence. They will serve as running examples throughout the tutorial.

Language recognition. A formal language is a set of finite strings over an alphabet Σ. A recognizer decides whether an input string belongs to that set. We consider:

  • Parity: Accept a string over {𝑎,𝑏} exactly when it contains an even number of 𝑎 symbols. Encoding 𝑎 as 1 and 𝑏 as 0 gives the usual bit-parity problem. For example, aba is accepted and abb is rejected.
  • Dyck-1: Accept correctly nested parentheses of a single type. Every prefix must have at least as many opening as closing parentheses, and the final counts must agree. For example, ()(()) is accepted, while ())( is rejected despite having equal final counts.
  • Dyck with multiple bracket types: Require both correct nesting and matching bracket types. For example, ([]) is accepted, while ([)] is rejected. Unlike Dyck-1, counting opening and closing brackets alone cannot check that their types match.
  • Flip-flop: For a string over {𝑎,𝑏,𝑒}, accept exactly when the last non-𝑒 symbol is 𝑏. The symbol 𝑒 is neutral: appending it leaves the decision unchanged. For example, abee is accepted and baee is rejected. Strings with no 𝑎 or 𝑏, including the empty string, are rejected.

Sequence generation. Copying asks the model to produce an output sequence rather than an acceptance decision. After reading an input and a separator, it must reproduce the input in the same order. Following Huang et al. (2025, Appendix E.2.1), an example is SOS b a b SEP b a b EOS. The paper distinguishes Copy (repeat), with inputs over a binary alphabet that may contain repeated symbols, from Copy (unique), in which all input tokens are distinct. Training loss is applied to the copied sequence and the final EOS token.

Transformer equations and numerical assumptions

Inputs and positions. Let 𝑤=𝑤1…𝑤𝑛 be a word over a finite alphabet Σ. We prepend a special beginning-of-sequence token, 𝑤0=BOS, and write 𝑚=𝑛+1 for the total sequence length. At each position 𝑖, the model maintains a vector ℎ𝑖ℓ∈ℝ𝑑 after layer ℓ. The initial vector is

ℎ𝑖0=𝑒(𝑤𝑖)+𝑝𝑖,0≤𝑖≤𝑛,

where 𝑒 maps token identities to learned vectors. The optional vector 𝑝𝑖 supplies explicit positional information:

  • With no positional encodings (NoPE), 𝑝𝑖=0 at every position. Positions can nevertheless have different representations because causal attention gives them access to different prefixes.
  • With absolute positional encodings (APE), each supported position has a learned vector 𝑝𝑖. The positional table is finite, so a fixed model supports only a finite context window. We discuss how offsets and increasing context lengths enter the generalization framework below.

Logit scaling and uniform attention. Ordinary softmax attention uses 𝑠𝑚=1. Huang et al. instead use 𝑠𝑚=log𝑚, making the scale depend explicitly on sequence length. For positive 𝑠𝑚, the ratio between two attention weights is

𝛼𝑖,𝑗𝛼𝑖,𝑡=exp(𝑠𝑚(𝑎𝑖,𝑗−𝑎𝑖,𝑡)).

Thus scaling changes how strongly the head distinguishes unequal scores. If all visible scores are equal, however, every visible position receives weight 1𝑖+1. This is the uniform attention used later to represent prefix counts. The usual fixed factor 1𝑑𝑘, where 𝑑𝑘 is the query/key dimension, can be absorbed into the learned query or key matrices. Numerical precision. Huang et al. round attention logits and the outputs of the exponential function to a fixed number 𝑝 of fractional bits before further processing. Rounding to 𝑝 fractional bits restricts these quantities to multiples of 2−𝑝; it does not impose a fixed total bit budget on every number in the computation. The circuit upper bound discussed next has its own precision assumptions and should not be transferred to this model without checking them.

For recognition, the output at the final input position 𝑖=𝑛 determines acceptance; for example, a binary readout can compare acceptance and rejection logits. A single forward pass applies the 𝐿 layers once. For a fixed transformer, its parameters, depth, width, and head count do not grow when the input gets longer. Autoregressive generation instead uses the output to append a token and runs another forward pass, introducing additional computation that we consider separately in the chain-of-thought section.

Forward-pass Expressivity

We first ask which languages a fixed transformer can recognize in a single forward pass. Its depth 𝐿, width 𝑑, and number of heads 𝐻 are independent of the input length. Increasing the input length adds positions to the computation, while the number of layers remains fixed.

The circuit classes introduced in the complexity background make this parallel structure precise. Merrill and Sabharwal (2023) show that transformers using 𝑂(log𝑛) bits of arithmetic precision, with feedforward maps computable in space linear in their input representation, can be simulated by logspace-uniform 𝖳𝖢0 circuits. This is an upper bound on their forward-pass expressivity, not a claim that every such circuit can be represented by a transformer.

The precision assumption matters: Huang et al.‘s model permits unbounded-precision activations, so this circuit bound does not apply to it directly. Nor does the bound characterize C-RASP: for example, 𝖳𝖢0 contains parity, whereas C-RASP does not. We consider autoregressive generation, which runs further forward passes to generate additional tokens, in the chain-of-thought section.

Definition

A C-RASP program is a fixed finite sequence of assignments defining vectors indexed by input positions. Boolean-valued vectors represent predicates on positions; count-valued vectors assign an integer to each position. Assignments are evaluated in sequence, each defining a whole vector from the input and previously defined vectors. Both the number of assignments and the permitted operations are independent of the input length.

Our running example is Dyck-1, the language of correctly nested parentheses over the alphabet Σ={(,)}. We will trace the program on the input ()(()).

Input representation. We assume that inputs are words over a finite alphabet Σ, corresponding to tokens in a transformer. For each character 𝑎∈Σ, we create an initial Boolean vector 𝑄𝑎∈{0,1}𝑛, where 𝑛 is the input length. Its entry 𝑄𝑎(𝑖) is 1 if the input character at position 𝑖 is 𝑎, and 0 otherwise. In other words, each 𝑄𝑎 marks all the positions containing the character 𝑎.

The two input-marker vectors for our example are:

𝑄(=[1,0,1,1,0,0],
𝑄)=[0,1,0,0,1,1].

Both kinds of vectors have one entry per input position, but their entries mean different things. A Boolean-valued vector answers a yes-or-no question at each position: for example, 𝑄((𝑖) says whether position 𝑖 contains an opening parenthesis. A count-valued vector instead stores a number at each position: 𝐶((𝑖) tells us how many opening parentheses have appeared from the start through position 𝑖. Thus, 𝑄( marks individual tokens, while 𝐶( summarizes prefixes. Prefix counting turns a Boolean predicate into counts; comparing counts, as in 𝑉(𝑖) below, produces a Boolean predicate again.

We now combine these markers into a recognizer.

Prefix counts. First, count how many opening and closing parentheses have appeared up to each position. The notation #[𝑗≤𝑖]𝑃(𝑗) counts the positions 𝑗 up to 𝑖 where the predicate 𝑃 is true:

𝐶((𝑖)≔#[𝑗≤𝑖]𝑄((𝑗)
𝐶)(𝑖)≔#[𝑗≤𝑖]𝑄)(𝑗)

For ()(()), these vectors are 𝐶(=[1,1,2,3,3,3] and 𝐶)=[0,1,1,1,2,3]. Each entry records the count at the corresponding prefix.

Prefix violations. A valid string must never close more parentheses than it has opened. Mark each position where this condition fails:

𝑉(𝑖)≔𝐶((𝑖)<𝐶)(𝑖)

For ()(()), no prefix has more closing than opening parentheses, so 𝑉=[0,0,0,0,0,0].

Then count the positions marked as violations and check whether that count is zero:

𝐶𝑉(𝑖)≔#[𝑗≤𝑖]𝑉(𝑗)
𝑀(𝑖)≔𝐶𝑉(𝑖)=0

For this input, 𝐶𝑉=[0,0,0,0,0,0] and 𝑀=[1,1,1,1,1,1]. In general, 𝑀(𝑖) is true exactly when no prefix ending at or before 𝑖 has violated the nesting condition.

Balanced prefixes. The final condition is that the prefix has equally many opening and closing parentheses:

𝐵(𝑖)≔𝐶((𝑖)=𝐶)(𝑖)
𝐷(𝑖)≔𝑀(𝑖)∧𝐵(𝑖)

For this input, 𝐵=[0,1,0,0,0,1] and 𝐷=[0,1,0,0,0,1]. The prefix () is balanced at position 2, and the entire string is balanced at position 6. Following Yang and Chiang (2024, Definition 3.1), a recognition program must end with a Boolean-valued operation 𝐷 and accepts a word 𝑤 exactly when 𝐷(|𝑤|) is true. Here, 𝐷 is the output vector, and 𝐷(6)=1, so ()(()) is in Dyck-1.

The two conditions are both necessary. The string ())( has equal total numbers of opening and closing parentheses, but it has already closed one too many at position 3. It therefore fails the prefix condition and is rejected.

Semantics of prefix counting. The operator #[𝑗≤𝑖]𝑃(𝑗) counts the positions from 1 through 𝑖 at which 𝑃 is true, including position 𝑖 itself. Identifying false with 0 and true with 1, this means

For example, 𝑃=[1,0,1,1] gives 𝐶=[1,1,2,3]. The result is 0 when no position in the prefix satisfies 𝑃.

As in the paper’s examples, we use derived shorthand: 0 can be defined as 1−1, equality by two opposite ≤ comparisons, and 𝐶1<𝐶2 by ¬(𝐶2≤𝐶1).

From programs to transformers

How attention and feedforward computations implement C-RASP operations, including the numerical assumptions used by the construction.

C-RASP provides a constructive lower bound on transformer expressivity: any C-RASP program can be simulated by a suitable transformer. Boolean operations are encoded by the transformer’s feedforward layers, while prefix counting is implemented through attention.

The central idea is that uniform causal attention averages a predicate over the visible prefix. The resulting normalized counts share a positive denominator at each position, so comparing them gives the same answer as comparing the integer counts.

Derivation: prefix counting with uniform attention

For an input over a finite alphabet Σ, represent the token at position 𝑖 by a one-hot vector 𝑥𝑖∈{0,1}{|Σ|}, where 𝑥𝑖[𝑎]=1 exactly when the token is 𝑎. These coordinates are precisely the C-RASP indicators 𝑄𝑎(𝑖). A standard transformer’s token-embedding matrix maps this one-hot representation (or its equivalent token ID) to a learned vector.

Counting with attention. Following Counting Like Transformers (Yang and Chiang, 2024), the key idea is that attention can aggregate a predicate over a prefix. At position 𝑖, a causally masked attention head assigns position 𝑗 the weight

𝛼𝑖,𝑗=exp(𝑞𝑖⋅𝑘𝑗𝑑𝑘)∑𝑡≤𝑖exp(𝑞𝑖⋅𝑘𝑡𝑑𝑘),𝑗≤𝑖.

Set 𝑞𝑖⋅𝑘𝑗=0 for every visible position 𝑗 (for example, set all keys to zero). Each softmax score is then exp(0)=1, so its normalized weight is 𝛼𝑖,𝑗=1𝑖. With values encoding 𝑃(𝑗), attention returns

Att(𝑥)𝑖=∑𝑗≤𝑖𝛼𝑖,𝑗𝑃(𝑗)=1𝑖∑𝑗≤𝑖𝑃(𝑗)=#[𝑗≤𝑖]𝑃(𝑗)𝑖.

Thus attention can encode the C-RASP prefix count 𝐶(𝑖)≔#[𝑗≤𝑖]𝑃(𝑗) as the normalized count

𝐶̃(𝑖)≔𝐶(𝑖)𝑖.

At each position 𝑖, count values share the positive normalization factor 1𝑖, so comparisons between them are unchanged. Counts can also be combined using arithmetic and conditional selection, as described below. Constants must use the same encoding: the integer constant 1 is represented by 1𝑖, and more generally a constant 𝑐 by 𝑐𝑖.

For Dyck-1, for example, 𝐶( becomes 𝐶(̃=[1,1/2,2/3,3/4,3/5,1/2]. Both opening- and closing-counts share divisor 𝑖, so their comparisons-and hence the prefix-balance test—are unchanged.

Arithmetic and numerical precision

Sums, differences, minima, maxima, and conditional selection also preserve this shared divisor, allowing normalized counts to flow through the program. Distinguishing adjacent normalized counts requires resolution on the order of 1𝑖, so a fixed number of fractional bits cannot suffice at arbitrary lengths. This motivates allowing logarithmic precision for these attention results: for inputs of length at most 𝑛, log2(𝑛)+𝑂(1) fractional bits give resolution finer than the smallest adjacent-count gap 1𝑛. This observation concerns the resolution of the normalized counts, rather than a guarantee that rounding every intermediate computation to this precision preserves the full simulation.

Constants and the BOS token

The simplified calculation above omits the beginning-of-sequence (BOS) token used in the full construction. With BOS preceding the 𝑖 ordinary input tokens, uniform attention averages over 𝑖+1 positions. Assigning value 1 at BOS and 0 elsewhere therefore yields 1𝑖+1, the normalized encoding of the integer constant 1. Ordinary predicates are false at BOS, so their counts are encoded as 𝐶(𝑖)𝑖+1. Counts and constants thus share the same denominator (Yang and Chiang, 2024, Appendix B.2).

How LayerNorm is handled

For clarity, this explanation omits LayerNorm, but it can be accounted for in the compilation. Yang and Chiang (2024, Section 5.2 and Appendix B.3) use paired coordinates with opposite signs, ensuring zero mean so that LayerNorm applies a shared scaling factor at each position. Their construction handles this scaling when implementing Boolean values and count comparisons.

Putting these constructions together, any fixed C-RASP program can be compiled into a transformer whose depth and width are independent of the input length.

This compilation establishes representability, but does not imply that training will find the constructed solution. Empirical studies nevertheless find that C-RASP expressibility predicts length generalization on a range of algorithmic and formal-language tasks (Huang et al., 2025).

Positional information

How positions enter the model, from finite positional tables to limit transformers and positional predicates.

So far, we have not used explicit positional embeddings. Positions are distinguished only by their tokens and the information available from their prefixes through causal attention. Positional embeddings provide an additional, explicit representation of where each token occurs. Here we consider absolute positional embeddings: each position 𝑖 has its own learned vector 𝑝𝑖, which is added to the token embedding 𝑒(𝑥𝑖):

ℎ𝑖=𝑒(𝑥𝑖)+𝑝𝑖.

Finite positional tables and offsets

The position vectors are stored in a finite table, so the model is defined only up to its maximum context length 𝐿. To train the embeddings across this table using shorter examples, the offset trick assigns an example of length 𝑘 the positional vectors 𝑝𝑜+1,…,𝑝𝑜+𝑘 for a valid offset 𝑜. Varying the offset allows training examples to occur throughout the context window, but does not guarantee that every position is observed in a finite training run or teach the model to generalize to longer examples. Since the table is still finite, the C-RASP simulation cannot be realized by one such fixed transformer for inputs of arbitrary length. Instead, consider a sequence of transformers with increasing context lengths and corresponding positional tables. To describe the underlying computations across these context lengths, the framework introduces a mathematical object called a limit transformer.

Limit transformers

A limit transformer is an idealized model that captures the positional information provided by positional embeddings while remaining defined on inputs of arbitrary length. It has fixed width and finite-precision parameters. Besides positional vectors 𝑝𝑖, it can use an additional positional function in each attention head. Writing 𝑖 for the query position and 𝑗 for the key position, the attention logit has the form

𝑎𝑖,𝑗𝑙,ℎ=𝑞𝑖𝑙,ℎ⋅𝑘𝑗𝑙,ℎ+𝑟𝑙,ℎ(𝑖,𝑗).

The term 𝑟𝑙,ℎ(𝑖,𝑗) directly expresses a relation between positions, such as whether 𝑗 immediately precedes 𝑖. This allows the model to describe positional interactions at every input length without storing a separate learned vector for every position in a growing table.

For the length-generalization result, the positional vectors must be periodic, and the additional positional functions must be translation-invariant and local. Below, 𝑟 denotes the positional function of one attention head, with query position 𝑖 and key position 𝑗≤𝑖.

Periodicity. The positional vectors repeat with a fixed positive integer period Δ:

𝑝𝑖+Δ=𝑝𝑖for every𝑖≥1.

For example, period 2 allows alternating vectors (𝑢,𝑣,𝑢,𝑣,…) for odd and even positions. The sequence is infinite, but only Δ vectors need to be specified, independently of the input length.

Translation invariance. Shifting both positions equally leaves the interaction unchanged:

𝑟(𝑖+𝑠,𝑗+𝑠)=𝑟(𝑖,𝑗)for every integer𝑠≥0.

For example, assigning score 1 to the preceding position and 0 elsewhere treats (2,1) and (8,7) identically. Singling out absolute position 𝑗=1 would violate translation invariance.

Locality. The additional positional interaction vanishes beyond a fixed nonnegative integer distance 𝜏:

𝑟(𝑖,𝑗)=0whenever𝑖−𝑗>𝜏.

The preceding-position example is local with 𝜏=1. Assigning score 1 at every even distance is translation-invariant but not local. This restriction applies only to 𝑟; content-based attention can still aggregate over the entire prefix.

Positional information in C-RASP

We can express the same kinds of information at the program level by extending C-RASP to C-RASP[Φ,Ψ]. Here, Φ is a collection of Boolean predicates on individual positions, and Ψ is a collection of Boolean relations between pairs of positions. We add positional predicates

𝑃(𝑖)≔𝜑(𝑖),𝜑∈Φ,

and allow counting to be restricted by a positional relation:

𝐶(𝑖)≔#[𝑗≤𝑖,𝜓(𝑖,𝑗)]𝑃(𝑗),𝜓∈Ψ∪{⊤}.

This counts positions 𝑗 for which both 𝑃(𝑗) and 𝜓(𝑖,𝑗) hold. Ordinary prefix counting remains a separate allowed primitive, represented here by the always-true relation ⊤. The locality restriction applies to relations in Ψ, not to this unrestricted prefix-counting operation.

For example, a unary predicate 𝜑(𝑖) can mark the even positions. A binary relation 𝜓(𝑖,𝑗) can hold exactly when 𝑗=𝑖−1. Counting with this relation gives 1 if the preceding position satisfies 𝑃, and 0 otherwise, including when no preceding position exists. Comparing this count with 0 therefore lets a program test the preceding token.

When the predicates in Φ are periodic and the relations in Ψ are translation-invariant and local, we obtain the variant we denote by C-RASP[Pos] throughout this tutorial. This abbreviates the notation C-RASP[periodic,local] used by Huang et al. (2025). The position-free language introduced earlier is the special case with no added positional predicates or relations.

Length generalization guarantees

What the idealized learning framework guarantees, and what it leaves unresolved about practical training and required input lengths.

A C-RASP program specifies one computation that works at every input length. Compiling it into a transformer establishes that the computation is representable. Length generalization asks a further question: can a learner identify such a computation from its behavior on shorter inputs?

Training length and context length

To formalize this question, we must separate the lengths seen during training from the lengths the model can process. A model with context length 𝑛 can be tested on longer examples than it has seen, but only up to length 𝑛. Success within one fixed window therefore cannot establish generalization to arbitrarily long inputs. Huang et al. (2025) address this by considering a sequence of transformers 𝑇𝑛 with increasing context length 𝑛. For each 𝑛, an idealized learner observes the target function 𝑓 on all inputs of length at most 𝑛2 and selects 𝑇𝑛. We ask whether, for every sufficiently large 𝑛, this model also computes 𝑓 correctly on all unseen lengths between 𝑛2 and 𝑛.

This definition captures the idea that, once the learner has seen sufficiently long examples, its solution continues to work at greater lengths. Increasing the context window prevents the model’s finite positional table from setting an arbitrary ceiling on the analysis, while leaving the longer inputs unseen makes extrapolation necessary. The factor of two is a convenient choice, rather than an essential assumption of the framework. Observing all inputs through the training length also isolates generalization across lengths from the separate problem of learning from a finite sample. The resulting guarantee concerns this idealized inference procedure; it does not say that one trained finite-context model can process inputs of every length.

The idealized learner

The learner must fit every input through the training length and approximately minimize a complexity regularizer. Its positional contributions must also satisfy an offset-independence restriction. This is an idealized inference procedure; ordinary gradient-based training need not satisfy these assumptions.

Formal selection rule and positional restrictions

The selection rule requires 𝑇𝑛 to match 𝑓 exactly on all inputs through the training length and to approximately minimize a particular complexity regularizer among the models that do so. This regularizer controls quantities such as depth, precision, parameter norms, and positional interactions. The width 𝑑 is not explicitly bounded by the hypothesis class. More precisely, let 𝑈𝑛 be the set of admissible models that match 𝑓 on all inputs of length at most 𝑛2, at every valid offset. The procedure selects 𝑇𝑛∈𝑈𝑛 satisfying

ℛ︀(𝑇𝑛)≤inf𝑇∈𝑈𝑛ℛ︀(𝑇)+1𝑛.

Why approximate minimization? An exact minimizer need not exist: the infimum may not be attained by any model in 𝑈𝑛. The allowance 1𝑛 makes approximate minimization sufficient, with an error that vanishes as 𝑛 grows (Huang et al., 2025, Definition 6).

A separate restriction concerns how the model uses positional information. Although the embeddings 𝑝𝑖 may vary across positions, the parameter products through which they contribute to the computation must be unchanged when all positions are shifted equally. This is stronger than requiring the same final prediction at every offset: the underlying computation must use positional information in the same way. For example, an interaction based on the distance between two positions survives such a shift, whereas one tied to a particular absolute position generally does not.

The main equivalence

Under the framework’s assumptions, Huang et al. (2025, Theorem 7) establish that the following statements are equivalent:

  1. Representation: The target function 𝑓 is representable by a limit transformer with periodic positional vectors and translation-invariant, local additional positional interactions.
  2. Identification with bounded complexity: Any sequence 𝑇𝑛 selected by the idealized inference procedure has uniformly bounded regularizer values and eventually generalizes. That is, there are constants 𝐶 and 𝑁0 such that ℛ︀(𝑇𝑛)≤𝐶 for every 𝑛, and for every 𝑛>𝑁0, 𝑇𝑛 matches 𝑓 on all inputs of length at most 𝑛, despite having fitted it only through length 𝑛2.

The forward direction shows that such a representation guarantees eventual generalization with bounded complexity under the inference procedure. The reverse direction shows that a sequence selected by this procedure with both properties implies the existence of such a representation. Bounded regularization is part of this equivalence: eventual generalization alone is not the condition being characterized.

The procedure itself requires approximate minimization of the regularizer, rather than a prescribed uniform bound 𝐶. When the representation in the first statement exists, the theorem guarantees that the selected sequence remains uniformly bounded.

Intuition: eliminating incorrect candidate algorithms

Why is this possible? Under the theorem’s assumptions, bounded complexity leaves only finitely many candidate underlying algorithms. Any incorrect candidate disagrees with 𝑓 on some finite input. As the training length increases, that input eventually becomes visible and rules out the candidate. Once every incorrect candidate has been eliminated, the remaining algorithms agree with 𝑓 at every length. This is a statement about the computations identified by the learner; it does not require the parameter vectors to converge to a unique set of weights.

What follows for C-RASP?

The compilation introduced above connects C-RASP[Pos] directly to the main equivalence: every such program supplies a limit-transformer representation satisfying the theorem’s restrictions. Expressing a target function in C-RASP[Pos] therefore guarantees eventual generalization with bounded regularization under the idealized inference procedure. This is a sufficient condition; the converse claim that every such limit transformer has an equivalent C-RASP[Pos] program is not established.

How much training length is enough?

Eventual identification does not provide a practical stopping rule. Yang et al. (2026), in Length Generalization Bounds for Transformers, show that no computable bound in terms of program description size exists for general C-RASP, even at counting depth two, with a corresponding result for the transformer model considered there. This concerns the maximum input length needed to distinguish candidate programs, rather than simply the number of training examples. The same work also identifies a restricted positive fragment, C-RASP+, for which a computable bound does exist: the required training length is exponential in program description size, and this bound is optimal in the worst case. This fragment restricts count comparisons to nonnegative linear combinations of counts against constants. It is expressively equivalent to the paper’s fully fixed-precision transformer model, for which the authors also obtain exponential bounds.
